# Fusion-MOA v0.9.4.5：源码发布与下一步

2026-09-11 · **候选源码；未部署，尚无本版本的实测提分结论。**

## 本次发布什么

完整代码位于 [`versions/v0.9.4.5/`](../versions/v0.9.4.5/README.md)：Gateway 入口、同版本运行模块、schema、依赖声明、启动脚本、平台部署模板与继承的测试文件。它是完整 v0.9.4.4 基线加共享证据增量，不是只发布四个修改文件，也不运行时导入旧版本目录。

仓库原有 `fusion_moa/`、`tests/` 和根 `pyproject.toml` 保留，仍代表最小 Pioneer R1 Python 框架；不要把它的包版本号与完整 Gateway 的版本号混为一谈。完整 v0.9.4.4 基线及更早版本继续留在作者本地，未在本次发布中覆盖。

后续维护入口为 [Fusion-MoA-Pioneer](https://github.com/tongjiu123/Fusion-MoA-Pioneer)。原 [Fusion-MoA-Pioneer-R1](https://github.com/tongjiu123/Fusion-MoA-Pioneer-R1) 单独保留并归档；新仓库继承其已有 Git 历史，再增加本候选。归档不等于删除或给旧仓库改名。

公开副本的机器路径改为可配置示例；作者本地的精确部署记录不改动。模型权重、定制推理镜像、运行日志、凭据、Benchmark 数据和离线依赖不随源码上传。

## 本轮改进及原因

| 之前的问题 | v0.9.4.5 的明确增量 |
| --- | --- |
| 快照裁剪后引用重新编号，协作阶段指向不同证据 | 源消息编号随快照传递；截断条目有标记 |
| 各协作阶段独立构造证据，任务背景或最新要求可能错位 | 共享有界协作证据；保留 D12 自身 system/user/Compact 上下文、最新 user 地位及 tools |
| 弃权、分歧或少数假设在综合时丢失 | 保留完整 Analyst 意见和依据，Integrator 忠实整理，不额外制造共识或无来源的新方向 |
| D12 只看到流畅摘要，难以使用具体建议 | 同时传递意见、probe、预期及证伪观察；允许部分采纳、拒绝或继续原路径 |

所有这些修改都位于原来的证据构造和私有协作传递路径。没有增加协作角色、投票门槛、持久记忆、新的循环阈值或额外恢复轮数。共享证据不是把 D12 的完整输入缩成 Analyst 的窗口；Soft Stall 也不是“已证明失败”。

## 不变的系统边界

```text
外部 Client / Agent
    │ messages + tools
    ▼
单一 OpenAI-compatible Gateway
    ├─ 普通 D12 路径
    └─ 按需协作：共享证据 → D16 / D9 / D13 → D13 Integrator
                                      │
                                      ▼
                             D12 自行判断与生成
                                      │
                        唯一最终 text / tool_calls
                                      ▼
                    外部 Agent 执行工具并继续循环
```

保留父版本的 Soft Stall（原有 16 个工具回合周期）、Hard/Result Cycle、Episode、Panel 复用、Clean Recovery、Output Contract Recovery、Rolling Compact Build/Reuse/Extend、流式输出、Thinking Normalizer 与可选辅助失败 fail-open。版本整理不改变采样预算和模型槽。

SWE-bench、Terminal-Bench、LiveCodeBench 只是外部调用方。Gateway 不识别题号，不维护测试题目表，不执行工具、抢救 Patch 或调用官方评分器。

## 调用与兼容

公共接口仍为 `POST /v1/chat/completions`。新模型名为 `fusion-moa-v0945-general`；同 D12 无协作对照为 `fusion-moa-v0945-solo-d12`。v0944/v0943/v0942 的 general 和 solo 别名继续接受。

别名兼容只表示新 Gateway 接受旧 model 字符串，**不表示任何公网路由已被切换**。实际版本看 `/health` 或 `X-Fusion-MOA-Version`。Trace 保留 `fusion-moa-v0944-trace-v1` 作为未改变的结构格式标签。

本包是 OpenAI-compatible Gateway；Claude Code 或其他使用不同协议的客户端仍需各自的兼容配置或外部协议桥。仓库不包含所有历史客户端、协议桥与 Benchmark Harness 的部署文件。

## 下一步

先在目标服务器将本候选连接到现有模型端点，保持当前模型、采样、协作周期和外部 Harness 配置不变。确认实际运行版本与普通回答、原生工具调用、流式及协作路径能正常衔接，再用已选定的小范围任务观察效果；暂不直接开始一整轮全量测评。

已有问题样本用于检查证据引用与意见传递是否正确；新 MoA 与同 D12-solo 的同题观察用于判断协作是否有帮助。两者都不能直接证明相对旧 MoA 的总体提分。自然运行未触发 Panel 时，如实记录未覆盖，不调整阈值来制造介入。

这次源码发布只进行了发布副本的 Python／shell 语法与文件依赖检查，未执行部署脚本、启动模型、运行 Benchmark 或新增测试流程。旧版本分数不作为 v0.9.4.5 的成绩。

## 需要保留的教训

过去把“新增功能列表”误当完整版本规格，曾漏接 Soft Stall；Result Cycle 也曾只完成检测而没传递完整周期给 Recovery。本轮因此保留完整父版本，仅修改明确的信息传递问题。不能只看模块存在或一次检查通过，就声称整条执行链及模型效果已经改善。

后续改动应写清“改了什么、保留什么、尚未验证什么”；严格检查若只为新增路径服务，不顺手收紧父版本行为。无需把这些经验扩成新监督系统或强制多轮审查流程。
